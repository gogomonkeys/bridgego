# Operator checkpoint scopes (local implementation)

The secure cookie is only a process-local workflow locator, bounded to 30 minutes from initial creation (never refreshed). It does not itself authorize reads or writes. Existing operation scopes remain five minutes; signed observations remain 60 seconds. Only the two fully verified metadata/history checkpoints can create a new next-stage scope: fresh same-operator Google proof, an independent 120-second read-only scope, and full native readback matching the server-held verified after-token are required. Cookie rotation occurs only after successful verification. Prior cookies, nonces and guards cannot operate in the new scope. No old proposal/digest is carried forward. The UI takes these checkpoints; an older client can still use its unexpired original scope without extending authority.

Known UNKNOWN, pending operations/proposals, readback mismatch, cancellation or clock rollback cannot renew. The absolute locator expiry also caps displayed scope expiry and cookie lifetime. A checkpoint login that itself times out is still terminal in this revision; only the initial pre-prepare, never-submitted login has the bounded restart path. Process restart does not recover these in-memory sessions.
