# 重建版操作邊界

此版本從 8fc9e0a 重建。先前遺失候選的測試結果不能算本版通過。
正式切換未啟用；線上驗證另以授權的新合成資料表進行。

## 首次切換

- 固定設定限定單一資料表、dataset、服務、workspace、revision、Google audience、操作者 subject 與停寫來源。
- 四階段為唯讀準備、原生控制初始化、已核准舊紀錄納入、明確啟用。後三者各有預覽與執行，不合併成隱含副作用。
- B1/B2 是同程序中真正 ACK 及完整回讀所產生的私有證據；不是從 HTTP hash、環境變數或重新啟動還原的能力。
- UNKNOWN 一律停止，不自動重送、不退回 legacy writer。即使前一步確定成功，下一步仍可能停止；不得把整體停止解讀成前步未發生。
- 正常已啟用的同 JVM 季度流程不需要每季 Google 重新登入或外部短期簽章。首次切換期間的操作者 session 與外部觀察有短時限。

## 外部觀察來源

`ops/sign-cutover-observation.py` 只簽署獨立控制者已確認的 Render 觀察，不會抓取 Render、不會產生金鑰、不會送出請求，也不會因 challenge 自行認定部署已完成。
固定公鑰與核准 context 必須由既有受控設定提供；不得取用頁面傳入的新 key。
`observed` 的部署、單實例、服務、autoDeploy/previews 與觀察時間必須來自當次已驗證的 Render 來源。
簽章表示控制者對觀察負責，不是 Render 原生數位簽章，也不是刪除資料授權。
私鑰不得進入公開 repo、封存包、日誌或瀏覽器。

## 季度與重啟

先停止新遊戲，既有遊戲允許完成，排空已接受保存後才凍結、cleanClose 與季度清理。
逾時保持維護，不擅自判玩家負。帳號與已驗證生涯累計保留。
突發程序死亡仍可能遺失未持久化的最佳努力保存；本方案沒有宣稱消除此風險。
新 JVM 或未知操作仍保持維護，需人工唯讀對帳。單一服務與沒有其他寫入來源是操作假設，不是試算表提供的分散式鎖。
Google 版本歷史與外部備份不在資料表清理範圍。
