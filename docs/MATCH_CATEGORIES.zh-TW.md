# 固定正式場／休閒場與逐局耗時候選

2026-11-10，以 v0.12.2 (`43575d9`) 為基線。v0.13.0 發布內容；線上狀態以實際部署驗證為準，未改正式資料。已有結果頁短文案原樣保留。

## 開房與對局規則

- 開房固定 `roomType: FORMAL | CASUAL`，同房再開下一場沿用，不在結算時重新分類。大廳提供兩個入口及對應房間篩選。
- 正式場只允許四個不同真人工作階段、已知登入帳號不重複，四席連線並準備後才能開局；不能加入電腦。系統不能證明四個訪客工作階段背後一定是四個不同自然人。
- 休閒場允許真人／電腦混合，也允許四席都是真人；始終算休閒。原本的斷線電腦暫代與主動離開永久電腦接手維持。
- 舊客戶端未傳類型時預設休閒以維持原玩法；明確 null、空字串或不合法類型拒絕，不偷偷轉換。房間摘要、快照、遊戲及上一場封存都回傳類型。

## 正式場離開、斷線與裁定

- 主動離開記 `MANUAL_EXIT`，該隊判負；不補電腦，離開者不能重新加入原場。原參賽名單保留供結算，但已解除其房間占用。
- 最後一條連線中斷後保留 10 秒重連，期間暫停；另一個有效分頁仍在線不算斷線。原身分於期限前恢復即可續玩。逾時記 `RECONNECT_TIMEOUT`，該隊判負，不改電腦。
- 第一次確定失敗後進入固定 **1 秒裁定窗**，用以合併近乎同時送達的退出事件；對手在窗內也確定失敗則 `NO_CONTEST / BOTH_TEAMS_FAILED`，不計勝負或平手。
- 若第一次確定失敗時對手已在重連期限內，只等該席原本的 10 秒期限，不重設。對手恢復則原失敗方判負，對手也逾時則中止。之後才發生的新斷線不延長原裁定窗。
- 已逾時的玩家返回不撤銷失敗。已提交最後一張牌而鎖定 `SCORED` 的結果不受後續離開／斷線改寫。裁定窗內不繼續出牌。
- 同隊多人退出仍是該隊一場負；雙方無法可靠分出先後才中止。理由與失敗隊伍顯示於結果，尚未完成的牌面仍不公開。

## 統計與部分局

只計已確認保存的結果。正式／休閒的個人及整體彙總分開：

- `matches` 為已結束場次，包括正常完成、判負與中止；另提供 `scoredMatches`、`forfeitMatches`、`interruptedMatches`，不混稱全部正常完成。
- `SCORED` 依實際總分勝負／平手；`FORFEIT` 依退出／逾時失敗隊伍判勝負，不以當時領先分數決定；`NO_CONTEST` 不增加勝、負或平手。
- `completedDeals`、逐局耗時與累計分數只採已完成局。五局場打完兩局後終止，保留兩局，不補剩下三局或虛構分數。零局便終止也可記一筆已結束／判負或中止場次，完成局數和分數為 0。
- 原開局登入帳號與資格檢核都固定於開局；正式退出後在裁定窗內切換帳號不能改歸屬或造成漏存。休閒場中途由電腦接手不移轉帳號，也不為電腦建立個人戰績。退出者仍獲對應的判負或休閒結果，不能藉退出躲掉紀錄。
- 訪客能出現在整體場次，但沒有個人統計或入口；訪客名稱、識別碼不保存至統計紀錄，之後登入不補登訪客戰績。整體 API 是無身分彙總，私人原始明細仍含已登入者帳號，不宣稱整份明細已匿名。
- 未確認保存、缺全場同意、名單衝突或資料格式錯誤不補算。未新增勝率、排名或混合總榜。

## 同意與資料格式

新告知版本為 `statistics-v4`。全場開局真人都須在房間外確認新版說明，開局固定確認狀態；舊確認不能默認涵蓋退出判負／部分局保存。既有功能關閉、restricted／experiment 行為維持，未調整正式開關或權限。

沿用既有 JSON envelope，不新增工作表；私人 accounts 表在 E 欄增加 lifetime_statistics，2／4 欄舊格式仍可讀：

- `statistics_rule = fixed-room-type-v3`，新增 `lifetime_rule = account-career-v1` 表示新版確認允許生涯彙總。
- `room_type = FORMAL | CASUAL`，且 `match_category` 必須相同。
- `outcome = SCORED | FORFEIT | NO_CONTEST`；`reason`、勝方、實際完成局數及分數隨終局保存。
- 每席 `settlement_control = HUMAN | BOT`，保留既有歷程 `control_type = HUMAN | MIXED | BOT`。正式場禁止 BOT/MIXED；休閒中止可在最後真人離開時四席皆已轉電腦。
- 驗證完成局連續序號、數量不超過原選擇、正常完成須完成全部局、總分等於完成局分數加總、勝方與終局語意一致。季度清理／帳號移除保留新欄位與部分局事實。

## 個人本季／生涯

- 個人可切換本季／生涯，兩者仍分正式／休閒。主要顯示場數、勝場、勝率、積分，另列勝負／平手與三種終局數；整體只維持本季。
- 勝率 = 勝場 ÷（勝場＋負場＋平手），含退出判負，排除無勝負中止；分母為 0 顯示「—」，不是 0%。總場數仍包含中止，不能直接當勝率分母。
- 積分 = 每場實際完成局的我方結算分數總和，可為負。判負仍保留已完成局分數，勝負與積分不互相覆寫。
- 本季標示「結算至」台灣時間下一季度 1／4／7／10 月 1 日 00:00；此為 exclusive 切換點，不是最後一秒或資料讀取時間，也不表示會自動清理。
- 生涯只涵蓋功能啟用後有 `account-career-v1` 標記的已保存資料，顯示可證明的最早紀錄季度。舊紀錄無此保存同意不偷偷延長保留，已清除歷史也不回填，因此生涯不是對所有歷史的完整承諾。
- 季度人工清理在既有同一個原子寫入批次內，把過期合資格資料累加到帳號 E 欄，並刪除原始對局。carry 只保留正式／休閒數字、計分版本、已彙總至哪個季度邊界與最早季度，不保留場次ID、逐局耗時、對手名單或牌面。
- 相同已存場次只計一次；衝突或與既有 carry 截止範圍重疊時拒絕，不猜算。操作仍須停全部寫入者、明確確認、前後 digest 檢核及讀回；不明結果不得盲重跑。新一季尚未確認清理完成時，保存／統計讀取維持阻擋。
- 首次寫入 E 欄需要已驗證的工作簿有 A:E 容量；不足會拒絕，不自動擴欄或改 metadata。既有 2／4 欄 header 可在同批清理升為 5 欄，須先更新讀寫端與操作工具。
- 帳號刪除移除整個帳號 row（含生涯），原始紀錄歸屬移除，既有 erasure ledger 阻止舊身分資料復活；其他帳號生涯不變。Google 登入更新只改 A:D 並驗證 E 欄原樣保留。
- API 新增 `quarterEndsAt`、`lifetimePersonal`、`lifetimeCasualPersonal`、`lifetimeCoverage`、`lifetimeTrackedFromQuarter`。所有讀取以伺服器帳號為準；生涯或本季資料無法驗證時皆回不可用，不以本季冒充生涯或假的 0。

## 每局耗時與查閱

- 每個計分局第一次發牌前以伺服器單調時計起算，至第 13 墩最後一張牌提交且計分完成凍結，1／3／5 局各有一筆。
- 倒牌及全 Pass 重發保留同局起點；斷線等待、叫牌／決定時間與中間回合展示計入。最後 2 秒結果展示及局間最多 90 秒等待不計。
- 新保存紀錄含 `deal_timing_rule: elapsed-including-pauses-v1`，每筆 `completed_deals` 有非負整數 `elapsed_ms`。未完成局沒有完成紀錄或耗時，不另存精確逐局起訖時間。
- 即時／封存結果的 `elapsedMs` 可在每局明細、整場及上一場摘要查閱。統計 API 僅彙總，不新增原始個人明細入口或缺資料的平均耗時。
- 所有新遊戲結果能顯示本局耗時；持久保存仍受既有開關與全場新版確認守門。

## 歷史與相容

- v1 `four-humans-at-settlement-v1` 舊標記仍按原四真人正常完成規則列正式；v2 `match-category-at-settlement-v2` 仍保留原結算分類，不改寫成新開房語意。
- 無統計標記的舊資料不猜分類、不補歷史休閒或中止。舊資料無耗時顯示「無紀錄」，不補 0、不以整場時間平均回填。
- 舊 `personal`／`overall` 仍只表示正式；`casualPersonal`／`casualOverall` 表示休閒。不可用時四組皆 null，不顯示假的 0。
- 無正式資料遷移／回填。若候選啟用，讀寫端及操作工具須一起更新至可讀 v1/v2/v3 的版本；不要回退到拒絕新標記的舊程式或修改資料繞過檢核。
