# Read-only source cutover assessment (local candidate)

`CutoverAssessment` does not access Google, create a database, provide a lease or accept an environment flag as approval. The report contains no identity rows. Exact baseline tokens bind the configured target and canonical full native snapshot, including metadata.

* Missing native root: pure `LegacyToNativeCutoverPlan` supports an already complete typed snapshot only if it exactly fits the known eight-table schema and layout. It uses the existing retention ledger sheet as anchor, max sheet ID + 1 as nextSheet and adds root + receipt + journal in ONE batch. All cells, sheet IDs/dimensions and unrelated metadata remain. Unsupported formats produce `BLOCKED_SCHEMA`; no lifetime normalization, truncation or sheet resizing occurs. The production strict parser remains unchanged. `StrictNativeSheetsResource.decodeLegacyFull` now bridges complete native JSON through the unchanged bounded Streaming parser, explicitly rejects all existing metadata, and checks the fixed dataset. This is pure parsing, not a Google reader/factory; no live assessment of the production sheet was performed.
* Existing valid journal: `ALREADY_JOURNALED`, not permission to claim or repeat initialization.
* Strictly validated CLOSED native schema without journal: a read-only bootstrap candidate only. An explicit trusted external verifier must attest exact target/baseline/source approval, all old/manual/import writers stopped, restart prevented and no outstanding/late requests. No production verifier has been provisioned.

The bounded bootstrap uses the existing journal combined batch and receipt-slot uniqueness. It preserves every table cell, remains CLOSED and does not grant an owner session. Fresh baseline and freeze evidence are checked immediately before the sole dispatch. Approval expiry/revocation or changed baseline consumes this plan without sending. An exception consumes the plan too. Read-only reconciliation reports exact applied, unchanged-but-uncertain, or different-and-uncertain; unchanged is not proof that a delayed request cannot arrive. No retry or automatic reopening follows any classification.

The journal metadata initializer is a distinct authorization scope from ordinary writer sessions. It is not wired into the production factory and does not bypass `JournalSessionAuthority`. A new process cannot rely on this object's attempt flag for exclusion: independent external freeze/outstanding-request proof remains mandatory. No assertion here prevents an uncooperative third-party editor or provides a distributed lock. No deployment, Google calls or real data changes were performed.

Same-target root/journal metadata cannot fence a late legacy append that ignores metadata. Exact after-read proves only that observed snapshot. This plan never grants a writer session or destructive maintenance authority. A separately approved new-target copy with old-target preservation can isolate old in-flight requests, but requires tail reconciliation and is not performed here.

Provenance delta: StrictNativeSheetsResource has one explicitly marked package-private legacy preflight extension. Existing decodeFull and Streaming remain byte-identical after removing that block and package normalization; CoreProvenanceTest verifies the original source hash. Core rename-only count is now 29 of 31, not 30; the other intentional change remains the inert MaintenanceRelease. Both provenance manifests record the new hashes.
