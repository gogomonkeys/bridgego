# Staged routing readiness (local candidate)

Render's rolling deployment switches routing only after the new deployment becomes healthy; the predecessor terminates afterward. Requiring old termination before any new routing health creates a dependency cycle. Do not solve it by authorizing overlapping writers or mapping an unconditional liveness check to game readiness.

An explicitly installed trusted startup Factory can return `StagedNativeBackend`. It contains no actual backend or credentials: identity calls reject, saves reject, reads fail, and no legacy fallback exists. The ordinary default remains unavailable and fails startup without a factory. The coordinator waits only for this explicit STARTING proxy, not for arbitrary UNKNOWN storage. A trusted owner may poll authenticated read-only inventory, and only after predecessor exclusion and the appropriate native handoff proof call `activateOnce`. Attachment installs one verified backend and its lifecycle without replacing identity/statistics facades. Any activation exception is terminal; a caller cannot automatically retry an uncertain claim.

`/health/route` is distinct from `/health/ready` and `/health/live`. After ApplicationReadyEvent, a native deployment can serve a maintenance page with 200 routing health while all business routes and WebSocket admission remain blocked. It checks the real shared gate and native source and requires the domain frozen or still empty. ACTIVATING, FAILED/UNKNOWN and later quarterly maintenance can continue safely serving maintenance, avoiding a platform restart loop; this does not report healthy data. Startup failure, context close and shutdown return 503. OPEN/FINISHING serving uses the game readiness condition. `writeReady` is false for FINISHING and all closed admission states.

The formal Render health path is unchanged in this work. The production authenticated evidence loader, prerequisite polling/scheduling and actual credential-backed activation factory still require explicit assembly; the local Spring test injects a trusted synthetic factory and invokes activation. It verifies routing 200 alongside login/room/statistics/socket 503, success opening the same facades, and activation failure remaining maintenance-only. No Google/Render request occurs in these tests.
