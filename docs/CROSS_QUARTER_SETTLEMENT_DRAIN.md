# Registered-game settlement drain (local extension)

The ordinary native match/openRequired path remains unchanged. A separately marked Service.matchDrain extension accepts only a nonconstructible grant tied to an attached gate settlement permit for a previously registered game. The grant binds the match ID, last verified old boundary and current boundary; the native ledger must still be COMPLETE at that exact old boundary. The root must remain the same known OPEN owner, with no other pending native ticket or quarter operation.

The game's start must be inside the old verified interval and before the new boundary. Finish must be at/after its start and old boundary and no later than now. This covers both an old-quarter completion already queued before the boundary and an active game finishing in the new quarter. Full envelope/account/erasure validation is retained. Receipt/data/root/journal are still one atomic batch and the ticket is bound to the current admission boundary. No implicit rotation or cleanup is attempted by the drain method.

NativeStoresBackend uses settlement permits for queued writes and chooses the explicit drain method only after the verified boundary becomes older than the clock's quarter. Ordinary identity/profile admission is denied during FINISHING before touching native Service, so denial does not poison an otherwise healthy finishing writer. CONFIRMED settlement marks the registered game recorded before releasing its permit. Queue rejection/cancellation does not mark it recorded; only a definitely unsubmitted REJECTED status can be retried. UNKNOWN cannot be retried.

After all existing games and admitted writes drain, quarter cleanup folds old-finished records into lifetime and removes their old raw data; new-quarter finished records remain raw/current. Tests verify both cases and no unregistered/ordinary writer bypass. The core provenance test removes only the explicitly marked extension and still proves the original runtime bytes unchanged after package normalization. This is local implementation/testing, not a production cutover.
