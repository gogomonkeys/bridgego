# Same-source bounded session renewal (local candidate)

The original session limit remains at most one hour and 128 dispatched batches. A replacement capability is allowed only at an operation boundary while the old capability is READY or cleanly expired, with no prepared/pending/in-flight/unknown request. A fresh full journal-verified snapshot must exactly equal the last positively confirmed snapshot and retain the same target, source version and owner. External cutover evidence is revalidated, including its own revocation/expiry policy. The original approved-baseline token is preserved; a new snapshot does not manufacture a new approval.

JournalAuthoritySlot is shared between the bounded Google provider and Handle. Replacement closes the old authority instance before publication. Old references cannot arm, dispatch, acknowledge again or regain authority. The replacement duration cannot exceed its predecessor's granted duration (never more than one hour); its counter starts at zero. UNKNOWN, pending/in-flight/VERIFYING expiry, or clock-rollback sessions require a new externally verified recovery/cutover process, not renewal.

NativeStoresBackend checks renewal at the start of a native operation under the same Service serialization monitor and existing gate permit. It renews at 128 batches or within 60 seconds of expiry; renewal performs only full reads, no remote mutation, no rotation, no new owner claim. Queued permits remain accounted for. Failure closes the local Service and blocks the gate; queued operations cannot bypass that failure. Handle/provider safe close revokes the current authority and clears the token cache as before.

This is not a lease, remote lock, indefinitely valid approval or keepalive. External writer fencing remains separately required; a verifier that only trusts an old string is insufficient. Late/duplicate already-journaled writes remain governed by atomic receipt uniqueness and anchor fencing. Legacy writes without those controls still require explicit source-cutover evidence. Tests use a local model and fixed clock, not a real Google session.

Scope limit: this now also supports the same still-alive process waking after clean idle expiry. EXPIRED_CLEAN is assigned only when a READY authority with no pending/active dispatch normally reaches its deadline. Its existing Handle/provider permits fixed-target read-only scopes and GETs to verify a fresh full journal; it cannot arm or POST a mutation. Exact confirmed state, same owner/source/target and currently valid external cutover evidence are all required to replace the capability. A stale/mismatched read or revoked grant permanently blocks the session and closes/wipes provider resources. No alternate authentication or credential channel is added.

This does not authorize a new JVM to take over an OPEN root. A process restart still requires independently verified ownership/recovery. Real UNKNOWN can never be relabeled EXPIRED_CLEAN or renewed.
