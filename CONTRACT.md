# BridgeGo v0.7.2 contract — three-deal play and scoring

Local independent guest-session app. Four real players, no dummy/double/redouble. Server-authoritative private dealing, privilege, auction, play, completed-deal scoring and fixed three-deal match. Existing native transport remains unchanged.

## HTTP and command authority
Existing session/room endpoints unchanged: POST /api/sessions {displayName}; GET /api/me; GET/POST /api/rooms; POST /api/rooms/{id}/join; GET /api/rooms/{id}; PUT /api/rooms/{id}/ready {ready}; POST /api/rooms/{id}/leave. Bearer token identity only. No spectators or replacement game participants.

Commands:
- POST `/api/rooms/{id}/start` {actionId,expectedRevision}; host, four ready and connected only.
- PUT `/api/rooms/{id}/games/{gameId}/deals/{dealId}/privilege` {actionId,expectedRevision,use:boolean}.
- POST same deal prefix `/calls` {actionId,expectedRevision,type:"PASS"} or {actionId,expectedRevision,type:"BID",level:1..7,strain}.
- POST same deal prefix `/plays` {actionId,expectedRevision,card:{suit,rank}}.
- POST same deal prefix `/acknowledge-result` {actionId,expectedRevision}; one authenticated acknowledgment per seat.
- POST `/api/rooms/{id}/games/{gameId}/rematch` {actionId,expectedRevision}; current online host only, MATCH_RESULT only.
- GET `/api/rooms/{id}/last-match`; safe last terminal archive, authenticated original participant only (even if no longer a current member while room exists);403 others,404 no archive.
Each returns {actionId,outcome:"APPLIED"|"REPLAYED",appliedRevision,room:<personalized snapshot>}. UUID actionId is per-player; accepted exact retry returns current snapshot without repeating effects, even after deal transition. Different payload reusing ID gives ACTION_ID_REUSED. Fresh commands require exact revision/game/deal, phase, turn and legal action. Error {code,message}, no hands/tokens in errors. Authentication: 401; unauthorized: 403; stale/phase/turn/illegal action: 409; invalid shape: 400. No settlement performed by clients.

## Play, settlement and between-deal confirmation
Seat 0 is the first dealer; auction turns run leftward 0→1→2→3, with opposite teams NS (0/2) and EW (1/3). Waiting host departure transfers to lowest occupied seat. Each completed deal rotates dealer clockwise; all-pass redeal keeps dealer, increments redealCount, creates new dealId without incrementing completedDeals/dealIndex. First caller is current dealer.
Privilege per player yes/no immutable; any yes resolves team true, both no false; reveal both teams together. Shared 20-second phase budget, missing votes become no without overriding yes. Ascending bids level1..7, CLUB<DIAMOND<HEART<SPADE<NO_TRUMP. Three passes after bid immediately enter PLAYING; four opening passes redeal.
Opening lead is last bidder's right `(holderSeat+3)%4`. Play proceeds rightward `(seat+3)%4` (0→3→2→1), unlike leftward auction rotation. Each trick winner leads the next trick. Must follow led suit if held; otherwise any card. Highest trump wins, else highest led suit; Ace high; NT no trump. Each turn lasts 20 seconds; timeout picks lowest legal rank, ties CLUB/DIAMOND/HEART/SPADE (explicit deterministic implementation default), source TIMEOUT.
After every fourth card enter TRICK_RESULT for a shared authoritative 2,000 ms. play.currentTrick retains all four cards, nextSeat=null, and trickNumber/leaderSeat describe the completed trick. completedTricks includes that same trick, whose winnerSeat identifies the winning card. Clients must not double-count the retained currentTrick when reconstructing played-card history. No legal cards or next-player turn budget exists during this phase; derive per-seat current-deal wins from completedTricks. At expiry, nonfinal tricks return PLAYING with the winner leading and a fresh full 20-second PLAY_TURN budget. No UI animation or local timeout may advance the game.
On thirteenth trick score exactly once using confirmed calculator: attack success base=level, exact target 6+level adds level+1, failure -level; defence ordinary score 0; each used privilege +2 on team win/-1 loss. Typed breakdown includes total explicitly. Completed result persists; collected card faces remain redacted until the presentation transitions to settlement. After the final-trick presentation for deals 1/2 enter DEAL_RESULT with a shared 90-second budget, no new cards and empty remaining hands. Each authenticated participant may acknowledge once; all four acknowledgments advance early, otherwise budget expiry advances once. Fresh acknowledgment IDs after already acknowledging are harmless accepted no-ops; retries retain normal idempotency. Only advancing increments dealIndex/dealer, creates new dealId and private hands, clears acknowledgments, and starts a fresh 20-second PRIVILEGE_DECISION budget. The third-deal SCORED outcome locks immediately when the final fourth card is accepted, but its four-card presentation remains for 2,000 ms before MATCH_RESULT; higher total wins, equal totals winnerTeamId=null (draw).

## Timers, disconnect and final adjudication
Operation budgets use monotonic time and domain-lock serialization. Due timeout wins exact boundary against fresh action; accepted replay never resets time. Refresh never resets. Late sweeps advance at most one timed action, then start the next phase’s full budget (20 seconds for player operations, 90 seconds for DEAL_RESULT, 2 seconds for TRICK_RESULT); no catch-up chain. Snapshot remainingMs is sampled; no per-tick revision broadcasts. First offline member freezes operation timer; all reconnecting resumes remaining. DEAL_RESULT is active: disconnect freezes its 90-second budget and existing 10-second grace/forfeit applies; no confirmation can advance while paused. Ordinary TRICK_RESULT freezes on disconnect with the same 10-second grace. The final third-deal presentation is already scored and immutable: disconnect or explicit leave cannot forfeit it or freeze the transition to MATCH_RESULT. No operation timer in pending/MATCH_RESULT states.
WAITING detected last socket loss immediately releases seat/ready; another live tab preserves presence. Initial HTTP join has distinct 5-second subscription cleanup. During active game last socket loss starts that player's 10-second grace, preserving private state; no replacement player. Manual active leave immediately forfeits that player's team irrespective of current points. Completed scores remain; unfinished deal is not scored.
Reconnect grace authority uses monotonic time; exposed epoch reconnectDeadline is display-only. `forfeitEvents` attributes actual triggering players with safe IDs/seats/causes, resolving names through frozen roster; stale callbacks and terminal leaves add no events.
Network adjudication is deterministic: at first grace expiry mark that team failed. If opposing players already have unexpired reconnect grace, capture only those existing deadlines and wait paused. Each must recover within their own original grace; otherwise opponent also fails. No new disconnect can extend this fixed pending window. First failed team cannot undo failure by returning late. One failed team means other team wins; both failed means NO_CONTEST with no winner. During pending, opposing manual exit marks second failure/no-contest immediately; failed-team exit does not change outcome. Simultaneous expiry is both failed regardless iteration order.
MATCH_RESULT never changes after later closes/leaves. Terminal socket loss retains result-view membership (no running game/grace/replacement); explicit leave releases membership. This allows all-offline participants to return and inspect no-contest. An empty room after all explicit leaves can be removed. Host-controlled rematch is explicit: MATCH_RESULT→WAITING, retaining only currently online members and original seats, clearing all ready flags and per-game/grace/adjudication state. No new game/deal exists until normal host Start with4ready+connected. Room revision and accepted-action ledger are not reset; stale old-game commands and rematch retries cannot mutate a new match. Old offline members may rejoin only as fresh capacity-aware waiting participants.
Terminal host transfers to lowest occupied online seat when the host leaves or loses its last connection; no online participants means hostPlayerId=null, and first returning participant is elected. This applies equally to scored/forfeit/no-contest terminals. Waiting host transfer remains lowest occupied seat.
The last terminal match is copied into a safe MatchArchive before reset. Each archive value is immutable, but the retained projection refreshes on terminal transitions so final-trick card faces remain hidden until MATCH_RESULT and then become reviewable. It excludes unplayed hands, private choices, action ledger and credentials. Snapshot lastMatch and GET last-match reveal it only to original participant IDs, never a new guest taking an old seat. Public internal notifications have lastMatch=null. A newer terminal match replaces the last archive. All explicit leave deletes the room and its memory archive; restart also clears it. Room summaries expose WAITING/ACTIVE/FINISHED and phase; finished rooms are not mislabelled active and remain unjoinable until rematch. Existing members may still restore their terminal result access.

## Native WebSocket (not STOMP)
Connect `/ws`; first message within 5 seconds: `{"type":"subscribe","token":"...","roomId":"..."}`. Token never in URL. Membership is validated; cannot observe another room. Server emits `{"type":"snapshot","room":<snapshot>}`. Server errors `{"type":"error","code":"...","message":"..."}` then closes invalid subscriptions. The server sends native WebSocket control Ping frames every 2 seconds (at most one outstanding probe); the browser/network stack automatically returns matching control Pong frames without page JavaScript timers. The 6-second response deadline starts only after the actual Ping write completes. A probe missing its matching Pong for 6 seconds triggers application-defined close code 4001 (`HEARTBEAT_TIMEOUT`); 4001 is not a built-in WebSocket timeout. If an expired probe accumulated at least 2 seconds of evidenced local scheduling lateness after its actual write (sum of observation gaps exceeding the expected 250 ms scheduler cadence), the server performs one fresh verification probe before classifying the peer as dead. Earlier or cumulative sub-six-second stalls therefore remain visible; delay before the Ping write does not count. That exception is bounded to one retry per unanswered probe sequence; only a valid matching Pong resets it. No client JSON heartbeat or elapsed-time watchdog is required. Optional legacy `{"type":"ping"}` still returns `{"type":"pong"}`, but does not satisfy control-transport liveness. Client reconnect on close with bounded backoff (e.g. 0.5/1/2 seconds); after reconnect send subscribe again. Authoritative full snapshot recovers missed events. HTTP operations remain authoritative, WS receive-only except subscribe/heartbeat.


## Connection diagnostics (v0.1.3)
Server close reasons are bounded static labels, not tokens or request contents: 4001 `HEARTBEAT_TIMEOUT`, 4002 `SUBSCRIBE_TIMEOUT`, 4003 `MEMBERSHIP_ENDED`, 1008 `INVALID_SUBSCRIPTION_OR_MESSAGE`, 1011 `TRANSPORT_ERROR` / `SEND_FAILED` / `PING_SEND_FAILED` / `MESSAGE_INTERNAL_ERROR` / `OUTPUT_BACKPRESSURE` / `OUTPUT_WRITE_TIMEOUT` / `OUTPUT_EXECUTOR_REJECTED` / `OUTPUT_TASK_FAILED`. Server logs record connection ID, close code, bounded cause labels, probe age, scheduler gap, matched/mismatched Pong counts, recent RTT/write duration, queued/active write age, safe exception class and protocol failure code. They never record tokens, requests, hand data, guest names or untrusted exception/peer reason text. Peer closes use `PEER_CLOSED`. Client diagnostics may display the close code/reason. These distinguish transport failure from explicit membership revocation; the server does not log guest bearer tokens.

### Locking and write ordering
Domain transitions enqueue snapshots to a bounded (64 pending messages), per-connection ordered writer; they do not perform synchronous network writes under the room-state monitor. Native Pong handling uses only connection-local heartbeat state. Removed connections discard queued outbound snapshots; fresh joins use fresh socket IDs and cannot be removed by old callbacks. A fast Pong arriving before Ping send returns is not overwritten by send-completion bookkeeping. The normal 6-second detector setting is unchanged; no waiting-room reconnect grace has been added.

A queued or active writer that makes no progress for **15 seconds** is closed with 1011 `OUTPUT_WRITE_TIMEOUT`, independently of the 6-second Pong-response deadline. This bounds an executor that never runs or a write that never returns; it is not seat-retention grace. Output queue overflow, task failure and executor rejection also release membership with explicit 1011 causes. Socket close attempts never block the room-state or heartbeat scheduler thread.

privilege.canChoose is viewer-specific: true only during unpaused privilege selection when their own vote is absent and their own team is unresolved. It reveals no opponent choices.


## V0.6 auction retention

Game and archive auctionRounds include all started rounds, with each all-Pass redeal stored immutably before a new dealId. DealResult.auctionRounds contains that dealIndex's rounds, including redeals. Calls retain authenticated seat, bid/Pass, strain/level and MANUAL/TIMEOUT source, but no private privilege votes or hands. Names resolve against the original match roster.
