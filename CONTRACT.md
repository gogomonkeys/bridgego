# BridgeGo v0.10.0 contract — selectable 1/3/5-deal play and scoring

Local independent guest-session app. Four seats with at least one human and optional server-controlled computer players, no dummy/double/redouble. Server-authoritative private dealing, privilege, auction, play, completed-deal scoring and selectable 1/3/5-deal match (default 3). Existing native transport remains unchanged.

## HTTP and command authority
Existing session/room endpoints unchanged: POST /api/sessions {displayName}; GET /api/me; GET/POST /api/rooms; POST /api/rooms/{id}/join; GET /api/rooms/{id}; PUT /api/rooms/{id}/ready {ready}; POST /api/rooms/{id}/leave. Bearer token identity only. No spectators or replacement human game participants; active explicit leave may replace the seat with a permanent server bot.

Commands:
- POST `/api/rooms/{id}/bots` {actionId,expectedRevision,seat:0..3}; connected human host, WAITING only, empty seat.
- DELETE `/api/rooms/{id}/bots/{playerId}` {actionId,expectedRevision}; connected human host, WAITING only, bot target only.
- POST `/api/rooms/{id}/start` {actionId,expectedRevision}; host, four ready and present seats (connected humans or server-controlled bots) only.
- PUT `/api/rooms/{id}/games/{gameId}/deals/{dealId}/redeal` {actionId,expectedRevision,redeal:boolean}; eligible original player only during REDEAL_DECISION.
- PUT `/api/rooms/{id}/games/{gameId}/deals/{dealId}/privilege` {actionId,expectedRevision,use:boolean}.
- POST same deal prefix `/calls` {actionId,expectedRevision,type:"PASS"} or {actionId,expectedRevision,type:"BID",level:1..7,strain}.
- POST same deal prefix `/plays` {actionId,expectedRevision,card:{suit,rank}}.
- POST same deal prefix `/acknowledge-result` {actionId,expectedRevision}; one authenticated acknowledgment per seat.
- POST `/api/rooms/{id}/games/{gameId}/rematch` {actionId,expectedRevision}; current online host only, MATCH_RESULT only.
- GET `/api/rooms/{id}/last-match`; safe last terminal archive, authenticated original participant only (even if no longer a current member while room exists);403 others,404 no archive.
Each returns {actionId,outcome:"APPLIED"|"REPLAYED",appliedRevision,room:<personalized snapshot>}. UUID actionId is per-player; accepted exact retry returns current snapshot without repeating effects, even after deal transition. Different payload reusing ID gives ACTION_ID_REUSED. Fresh commands require exact revision/game/deal, phase, turn and legal action. Error {code,message}, no hands/tokens in errors. Authentication: 401; unauthorized: 403; stale/phase/turn/illegal action: 409; invalid shape: 400. No settlement performed by clients.

## Play, settlement and between-deal confirmation
Seat 0 is the first dealer; auction turns run leftward 0→1→2→3, with opposite teams NS (0/2) and EW (1/3). Waiting host departure transfers to lowest occupied human seat. Each completed deal rotates dealer clockwise; all-pass redeal keeps dealer, increments redealCount, creates new dealId without incrementing completedDeals/dealIndex. First caller is current dealer.
Privilege per player yes/no immutable; any yes resolves team true, both no false; reveal both teams together. Shared 20-second phase budget, missing votes become no without overriding yes. Ascending bids level1..7, CLUB<DIAMOND<HEART<SPADE<NO_TRUMP. Three passes after bid immediately enter PLAYING; four opening passes redeal.
Opening lead is last bidder's right `(holderSeat+3)%4`. Play proceeds rightward `(seat+3)%4` (0→3→2→1), unlike leftward auction rotation. Each trick winner leads the next trick. Must follow led suit if held; otherwise any card. Highest trump wins, else highest led suit; Ace high; NT no trump. Each turn lasts 20 seconds; timeout picks lowest legal rank, ties CLUB/DIAMOND/HEART/SPADE (explicit deterministic implementation default), source TIMEOUT.
After every fourth card enter TRICK_RESULT for a shared authoritative 2,000 ms. play.currentTrick retains all four cards, nextSeat=null, and trickNumber/leaderSeat describe the completed trick. completedTricks includes that same trick, whose winnerSeat identifies the winning card. Clients must not double-count the retained currentTrick when reconstructing played-card history. No legal cards or next-player turn budget exists during this phase; derive per-seat current-deal wins from completedTricks. At expiry, nonfinal tricks return PLAYING with the winner leading and a fresh full 20-second PLAY_TURN budget. No UI animation or local timeout may advance the game.
On thirteenth trick score exactly once using confirmed calculator: attack success base=level, exact target 6+level adds level+1, failure -level; defence ordinary score 0; each used privilege +2 on team win/-1 loss. Typed breakdown includes total explicitly. Completed result persists; collected card faces remain redacted until the presentation transitions to settlement. After the final-trick presentation for deals 1/2 enter DEAL_RESULT with a shared 90-second budget, no new cards and empty remaining hands. Each authenticated participant may acknowledge once; all four acknowledgments advance early, otherwise budget expiry advances once. Fresh acknowledgment IDs after already acknowledging are harmless accepted no-ops; retries retain normal idempotency. Only advancing increments dealIndex/dealer, creates new dealId and private hands, clears acknowledgments, and starts a fresh 20-second REDEAL_DECISION budget when anyone qualifies, otherwise PRIVILEGE_DECISION. The third-deal SCORED outcome locks immediately when the final fourth card is accepted, but its four-card presentation remains for 2,000 ms before MATCH_RESULT; higher total wins, equal totals winnerTeamId=null (draw).

## Timers, disconnect and final adjudication
Operation budgets use monotonic time and domain-lock serialization. Due timeout wins exact boundary against fresh action; accepted replay never resets time. Refresh never resets. Late sweeps advance at most one timed action, then start the next phase’s full budget (20 seconds for player operations, 90 seconds for DEAL_RESULT, 2 seconds for TRICK_RESULT); no catch-up chain. Snapshot remainingMs is sampled; no per-tick revision broadcasts. First disconnected human freezes the operation timer during the 10-second recovery grace. The game resumes the remaining budget after every unresolved disconnected seat has either recovered or entered BOT_TAKEOVER, provided at least one human is actually online. DEAL_RESULT and ordinary TRICK_RESULT follow the same grace; neither acknowledgments nor bot actions advance a paused game. The final third-deal presentation is already scored and immutable: disconnect or explicit leave cannot change it or freeze the transition to MATCH_RESULT. No operation timer advances a terminal outcome.
WAITING detected last socket loss immediately releases seat/ready; another live tab preserves presence. Initial HTTP join has distinct 5-second subscription cleanup. During an active game, last socket loss starts that player's 10-second grace (`controlMode: RECONNECTING`). When grace expires and another human remains online, the same identity, seat and hand enter `BOT_TAKEOVER`; playerType stays HUMAN, connected stays false, and reconnectDeadline becomes null. Re-subscribing with the original guest identity restores HUMAN control, cancels stale pending automated action, and returns a fresh private snapshot. A new guest cannot claim that seat. Already completed automated actions are not rolled back.
When the last online human disconnects, the room starts its own 10-second all-human recovery deadline (`allHumansReconnectDeadline`, epoch milliseconds); the game stays paused. Any original human returning within that room grace clears it. If none returns, terminate with NO_CONTEST, reason NO_HUMANS_CONNECTED, winnerTeamId=null and failedTeamIds=[]; no bot-only continuation. Grace authority uses monotonic time; exposed epoch deadlines are display-only.
Explicit active leave removes the original membership and immediately replaces that seat with a new permanent BOT identity (`playerType: BOT`, `controlMode: BOT`, connected=true). The departing player cannot reclaim it. If the explicit departure leaves no online human, terminate immediately with NO_CONTEST / NO_HUMANS_REMAIN rather than wait. If no human owners remain at all, the room is removed. Completed scores remain; unfinished play is not scored or exposed. Start-time roster remains frozen, so historical names are not rewritten to the replacement bot.
Temporary takeover rejects fresh redeal/privilege/call/play/result-ack commands from that disconnected owner with HTTP409 CONTROL_TAKEN_OVER; exact accepted replay remains read-only/idempotent. Legal action projections are empty and privilege selection disabled until control is restored by subscription. game.paused reflects the shared room pause; a takeover owner has no manual legal actions even when the shared game is running.
FORFEIT_PENDING, legacy forfeit reasons and forfeitEvents remain compatibility fields; the current disconnect/leave path does not adjudicate a losing team or add forfeit events. New no-human outcomes do not declare a winner.
No-human terminal rooms are closed: hidden from lobby, excluded from the active room capacity limit, and cannot rematch. Existing members can reconnect to inspect completed results for a fixed five-minute retention period; reconnecting does not extend that deadline. Unfinished cards remain private.
MATCH_RESULT never changes after later closes/leaves. Terminal socket loss retains result-view membership (no running game/grace/replacement); explicit leave releases membership. This allows all-offline participants to return and inspect no-contest. An empty room after all explicit leaves can be removed. For non-closed terminal rooms, host-controlled rematch is explicit: MATCH_RESULT→WAITING, retaining currently online humans and bots at original seats, clearing human ready flags while bots remain ready and per-game/grace/adjudication state. No new game/deal exists until normal host Start with4ready+connected. Room revision and accepted-action ledger are not reset; stale old-game commands and rematch retries cannot mutate a new match. Old offline members may rejoin only as fresh capacity-aware waiting participants.
Terminal host transfers to lowest occupied online human seat when the host leaves or loses its last connection; no online participants means hostPlayerId=null, and first returning participant is elected. This applies equally to scored/forfeit/no-contest terminals. Waiting host transfer remains lowest occupied human seat.
The last terminal match is copied into a safe MatchArchive before reset. Each archive value is immutable, but the retained projection refreshes on terminal transitions so final-trick card faces remain hidden until MATCH_RESULT and then become reviewable. It excludes unplayed hands, private choices, action ledger and credentials. Snapshot lastMatch and GET last-match reveal it only to original participant IDs, never a new guest taking an old seat. Public internal notifications have lastMatch=null. A newer terminal match replaces the last archive. All explicit leave deletes the room and its memory archive; restart also clears it. Room summaries expose WAITING/ACTIVE/FINISHED and phase; finished rooms are not mislabelled active and remain unjoinable until rematch. Existing members may still restore their terminal result access.

## Native WebSocket (not STOMP)
Connect `/ws`; first message within 5 seconds: `{"type":"subscribe","token":"...","roomId":"..."}`. Token never in URL. Membership is validated; cannot observe another room. Server emits `{"type":"snapshot","room":<snapshot>}`. Server errors `{"type":"error","code":"...","message":"..."}` then closes invalid subscriptions. The server sends native WebSocket control Ping frames every 2 seconds (at most one outstanding probe); the browser/network stack automatically returns matching control Pong frames without page JavaScript timers. The 6-second response deadline starts only after the actual Ping write completes. A probe missing its matching Pong for 6 seconds triggers application-defined close code 4001 (`HEARTBEAT_TIMEOUT`); 4001 is not a built-in WebSocket timeout. If an expired probe accumulated at least 2 seconds of evidenced local scheduling lateness after its actual write (sum of observation gaps exceeding the expected 250 ms scheduler cadence), the server performs one fresh verification probe before classifying the peer as dead. Earlier or cumulative sub-six-second stalls therefore remain visible; delay before the Ping write does not count. That exception is bounded to one retry per unanswered probe sequence; only a valid matching Pong resets it. No client JSON heartbeat or elapsed-time watchdog is required. Optional legacy `{"type":"ping"}` still returns `{"type":"pong"}`, but does not satisfy control-transport liveness. Client reconnect on close with bounded backoff (e.g. 0.5/1/2 seconds); after reconnect send subscribe again. Authoritative full snapshot recovers missed events. HTTP operations remain authoritative, WS receive-only except subscribe/heartbeat.


## Connection diagnostics (v0.1.3)
Server close reasons are bounded static labels, not tokens or request contents: 4001 `HEARTBEAT_TIMEOUT`, 4002 `SUBSCRIBE_TIMEOUT`, 4003 `MEMBERSHIP_ENDED`, 1008 `INVALID_SUBSCRIPTION_OR_MESSAGE`, 1011 `TRANSPORT_ERROR` / `SEND_FAILED` / `PING_SEND_FAILED` / `MESSAGE_INTERNAL_ERROR` / `OUTPUT_BACKPRESSURE` / `OUTPUT_WRITE_TIMEOUT` / `OUTPUT_EXECUTOR_REJECTED` / `OUTPUT_TASK_FAILED`. Server logs record connection ID, close code, bounded cause labels, probe age, scheduler gap, matched/mismatched Pong counts, recent RTT/write duration, queued/active write age, safe exception class and protocol failure code. They never record tokens, requests, hand data, guest names or untrusted exception/peer reason text. Peer closes use `PEER_CLOSED`. Client diagnostics may display the close code/reason. These distinguish transport failure from explicit membership revocation; the server does not log guest bearer tokens.

### Locking and write ordering
Domain transitions enqueue snapshots to a bounded (64 pending messages), per-connection ordered writer; they do not perform synchronous network writes under the room-state monitor. Native Pong handling uses only connection-local heartbeat state. Removed connections discard queued outbound snapshots; fresh joins use fresh socket IDs and cannot be removed by old callbacks. A fast Pong arriving before Ping send returns is not overwritten by send-completion bookkeeping. The normal 6-second detector setting is unchanged; no waiting-room reconnect grace has been added.

A queued or active writer that makes no progress for **15 seconds** is closed with 1011 `OUTPUT_WRITE_TIMEOUT`, independently of the 6-second Pong-response deadline. This bounds an executor that never runs or a write that never returns; it is not seat-retention grace. Output queue overflow, task failure and executor rejection also release membership with explicit 1011 causes. Socket close attempts never block the room-state or heartbeat scheduler thread.

privilege.canChoose is viewer-specific: true only during unpaused privilege selection when their own vote is absent and their own team is unresolved. It reveals no opponent choices.


## V0.6 auction retention

Game and archive auctionRounds include all started rounds, with each all-Pass redeal stored immutably before a new dealId. DealResult.auctionRounds contains that dealIndex's rounds, including redeals. Calls retain authenticated seat, bid/Pass, strain/level and MANUAL/TIMEOUT/BOT/BOT_TAKEOVER source, but no private privilege votes or hands. Names resolve against the original match roster.

## Computer players (local implementation, not a release declaration)

A human host can fill 1–3 empty waiting seats with bots, remove them, and start once all four seats are ready. Bots have explicit `playerType: "BOT"`, no bearer token, no fake socket, and no session membership. Their `connected: true` indicates server control, not a human connection. Existing room capacity and two-table beta cap apply. Bots cannot become host or keep a bot-only room alive. Human disconnection pauses bot actions during unresolved reconnect grace; after temporary takeover, play resumes only while a human remains online; terminal idle cleanup considers human connectivity only. Rematch retains bot seats and automatic readiness, and bots acknowledge inter-deal results automatically.

The existing synchronized sweep revalidates the current phase/turn and applies at most one paced bot action per room per sweep (normally 900 ms). No separate bot executor or client commands are used. Permanent bot choices/calls/plays are recorded as `BOT`; temporary human-seat automation is `BOT_TAKEOVER`, including automatically resolved privilege choices. Real-human timeout behavior remains `TIMEOUT`. Decisions use only that bot's own hand and public auction/current-trick data, never other private hands or an external AI service.

- Privilege: do not use; never override a teammate's committed choice.
- Auction: choose a longest held suit, random among ties, stable for the deal. Pass if partner currently holds the highest bid. Otherwise make the lowest legal bid in that suit up to level 2, or Pass. Do not bid no-trump.
- Lead: randomly choose a held suit, then its highest card.
- Follow-suit is always mandatory. On the fourth play, if partner currently wins, follow with the smallest lead-suit card. When void, prefer the smallest non-trump card; only if all remaining cards are trumps, play the smallest trump (which may overtake partner). No-trump makes all cards non-trumps.
- On the third play, apply the same partner-preserving choice only if no card outside the bot's own hand and current public trick could beat partner. For example, partner's trump king is safe when the bot holds the ace, so follow with a smaller trump if available. An unseen higher card or possible side-suit ruff prevents this guarantee; retain the ordinary strategy in that case. Past tricks and other hands are not inspected. A sole matching ace must still be played to follow suit.
- Otherwise, when following, play the smallest lead-suit card if even the largest cannot beat the actual current winning card; play the largest if it can win. The same trick comparator accounts for trump precedence, not raw cross-suit rank.
- Otherwise, when void, play the smallest trump beating every current table trump, or the smallest held trump if none has been played. If unable to cut, prefer the smallest non-trump card; only when no non-trump remains, play the smallest trump. In no-trump contracts every card is a non-trump. All minimum-rank ties are random.

Bot management preserves the existing idempotent command ledger and revision checks. Added errors include `INVALID_SEAT`, `SEAT_OCCUPIED`, `NOT_COMPUTER_PLAYER`, and `HOST_OFFLINE`; existing `HOST_ONLY`, `WRONG_PHASE`, and `STALE_REVISION` apply. No bot identity can authenticate to fetch a private hand.

## Optional low-point hand redeal (local implementation)

After every shuffle and before privilege, server computes A=4, K=3, Q=2, J=1, others=0. A hand qualifies if total<5, or total==5 with no Ace. If nobody qualifies, enter PRIVILEGE_DECISION directly. Otherwise enter REDEAL_DECISION with one shared 20-second budget, paused/resumed under the same disconnect rules. Every snapshot exposes only the viewer's yourPoints/eligible/yourChoice/canChoose; other players see no qualifying seats, point totals or choices. The public phase can reveal that somebody qualifies, but not who. Outside this phase yourPoints/yourChoice are null and both flags false.

Eligible humans may choose once: redeal=false commits to continue; after all eligible players decline, enter privilege with a fresh budget. redeal=true immediately reshuffles, changes dealId, clears choices and reevaluates eligibility; dealerSeat, dealIndex, completedDeals and teamTotals remain unchanged. Unanswered human choices default to continue on expiry. Eligible BOT and BOT_TAKEOVER seats choose redeal automatically using the existing paced scheduler, including a late-sweep fallback; no client or fake socket issues their commands. There is no forced cap that denies an eligible redeal. Repeated qualifying hands therefore may extend the start of a deal.

Each actual reshuffle increments redealCount; lastRedealReason is HAND_REDEAL or ALL_PASS. Both reset on the next scored dealIndex. Do not expose the initiating player or hand score. Hand redeals do not retain discarded empty auction-history rows. auctionRounds may contain one current IN_PROGRESS placeholder even before bidding, replaced rather than appended when that hand is redealt. Existing genuine all-Pass auction history remains preserved. The bounded latest reason/count describes hand redeals without an unbounded history of empty hands.

The redeal HTTP command uses the same authenticated identity, actionId/signature, expectedRevision and gameId/dealId checks as other commands. An accepted true replay returns current room without another shuffle. Fresh old-deal commands fail stale checks; concurrent requests cannot reshuffle the same hand twice. INVALID_REDEAL is HTTP400; REDEAL_NOT_ELIGIBLE and CHOICE_LOCKED are HTTP409. CONTROL_TAKEN_OVER prevents a disconnected owner racing automated takeover. Private qualification must never be logged or added to public error payloads.
